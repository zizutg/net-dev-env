## Environment 

For this exercise, use of Firefox or Chrome browser is good enough and
no other extra environment is required.

## Description

When a user enters a URL in a web browser, the browser first downloads the content and then renders it. A typical first in web performance analysis requires understanding of time taken in downloading and then rendering (formatted display, playing audio/video, open pdf file etc.) the web content. This exercise is focused on understanding and analyzing the web performance.

### Measuring Internet Access Speed

A typical internet access at home or office is currently available at
100Mbps or higher rates. Even the cellular 5G connectivity provides the
internet bandwidth at these rates. Typically, download (from the
internet) speed is much higher than then upload (to internet) speed.

As a first exercise, measure your download and upload speed. In the
browser, enter the URL <http://speedtest.net> and start the measurement.
This typically would take about few tens of seconds and provide the
details of both download and upload speed.

-   Use the URL <http://speedtest.net> (or any other similar URL
    provided by ISP) , Choose the server from which to run the speed
    test and start the test.

-   Analyze the result of speed test and ping performance. The ping
    response would be in tens of milliseconds.

-   Do a ping to your chosen hostname (e.g., umbc.edu) and compare the
    ping performance with speed test.

### Measuring Web Components

Though high internet connection speed is a must for better user
experience, there are other factors that also play significant role in
determining the user experience. A typical main URL for any organization
consists of number of components such as images, javascripts,
stylesheets etc., each having its own URL. Each of these URL are fetched
by the browser before the web page is rendered. A website like
<http://webpagetest.org> provides a detailed breakdown for each
component. This exercise involves analyzing the web performance of the
main web page of your organization. Carry out the following steps.

-   Access the website <https://www.webpagetest.org/> and enter the URL
    your chosen website (e.g. umbc.edu) to analyze its performance.

-   Analyze the Waterfall view of the website. For example, for
    umbc.edu, it will look as shown in Figure 1.

![](media/image1.png){width="3.5555555555555554in"
height="5.166666666666667in"}

Figure : Waterfall view of umbc.edu

-   Double clicking on this waterfall view to study more details about
    the performance. For this test, it shows website umbc.edu consists
    of 82 components and required 28 TCP Connections. For each of the
    URL, it provides request start time, DNS lookup time, download time,
    bytes downloaded and HTTP Status code.

-   A deeper analysis shows that URL Request \#44
    <https://umbc.edu/wp-admin/admin-ajax.php>, took more than 1 second,
    though bytes downloaded are 0.1KB.

-   Identify all such URLs in your chosen website which takes longer
    than 1s. This provides you some insight into overall performance of
    your website and provides pointers to areas which can be improved
    for better user experience.

#### Using Web Developer Tools

Most web browsers today provide support for analyzing web performance.
For example, in Firefox browser, before accessing a web page, setup the
Web Developer toosl as follows.

-   Open web developer tools in firefox

FirefoxTriple bar application menu (**≡**) More Tools Web Developer
tools.

This will open a sub-window as shown in Figure 2. For Chrome browser,
Web Developer Tools can be accessed as

Chrome Hamburger Menu (3 vertical dots) More Tools Developer Tools

. ![](media/image2.png){width="6.5in" height="1.9673611111111111in"}

Figure 2: Web Developer Menu

-   Enter the desired URL (e.g. umbc.edu) and while web page will be
    rendered in the main window, the sub window will show all the
    components URLs being fetched under the Network tab. The last line
    (Status) line will show summary performance.

-   Analyze the component URLs and identify the URLs that take maximum
    time. Clicking on a particular URL will provide more details for
    that URL, such as Request Timing for Waiting and Receiving. This
    will help you identify the bottleneck components that may need to be
    looked into to improve overall performance.
